# Shivani’s Baby Shower

Sunday, December 13, 2026 · Puja 10:00 AM · Lunch & Games 11:00 AM · The Courtyard Hall, Sunnyvale, CA. All times are Pacific. No street address or end time has been invented.

The original custom RSVP form is restored. It sends directly to the Google Apps Script supplied by the host in `code.text`. Google Forms is no longer embedded. Static HTML/CSS/JavaScript and original SVG artwork run on GitHub Pages without a framework, installation, or build step.

## Getting the RSVP form working

If you have already run `setup()` and deployed the supplied script:

1. In Apps Script, open **Deploy → Manage deployments**, select your web-app deployment, and copy its **Web app URL**, ending in `/exec`.
2. Paste that URL into `rsvpEndpoint` in `config.js`.
3. Commit and push the change. The website enables its form when a valid deployment URL is configured.
4. Open the published invitation, send a clearly labeled test response, and check the **RSVPs** and **Summary** tabs in your private Google Sheet. Remove your test entry afterward.

The source file itself does not contain its deployment URL. Never use the script editor URL or a `/dev` test URL.

If starting from scratch:

1. Create a private Google Sheet, then choose **Extensions → Apps Script**.
2. Replace the starter script with `google-apps-script/Code.gs` and save.
3. Select **setup** and click **Run**. Review and approve the spreadsheet permissions for your own script.
4. Confirm that the sheet now has **RSVPs** and **Summary** tabs.
5. Choose **Deploy → New deployment → Web app**. Set **Execute as: Me** and **Who has access: Anyone** so guests do not need to sign in. Deploy and copy the `/exec` URL.
6. Follow the configuration and testing steps above. Keep the spreadsheet’s sharing setting **Restricted**.

For code changes in Apps Script, saving is not enough: choose **Deploy → Manage deployments → Edit → New version → Deploy**. Updating the existing deployment preserves its URL. The repository contains the exact host-supplied script, so existing deployments of that script do not require a code change for this website integration.

## Guest count and your total

The website asks **Total people attending, including yourself**. You plus two guests means **3**, including children. Attending parties choose 1–10. Declines send **0** and clear attendance-only guest/dietary details. The count is visible before selecting attendance and hides only for a decline.

The supplied `setup()` creates the total automatically in **Summary → B1**:

```excel
=SUMIF(RSVPs!C2:C,"yes",RSVPs!D2:D)
```

This sums people, not form submissions. To correct an RSVP, update the original row in the private Sheet instead of adding another entry, so it is not counted twice.

## What the website sends

| Website field | Script parameter | Sheet column |
| --- | --- | --- |
| Guest / family name | `name` | B: Name |
| Attending | `attending` (`yes` or `no`) | C: Attending |
| Total people including yourself | `partySize` | D: Party Size |
| Not collected by this form | `email` (empty) | E: Email |
| Guest names, dietary needs, message | `notes` (labeled lines) | F: Message / Dietary Notes |
| Server timestamp | Generated by Apps Script | A: Timestamp |

The website confirms success only after Google returns `{ "result": "success", "row": 2 }` (or a later row). It uses a form-encoded POST with no custom headers and follows the Content Service redirect. It never uses `no-cors` or treats an unreadable response as proof of a save.

The supplied script appends every submission and does not deduplicate repeated requests. The website disables duplicate clicks while sending. If a timeout or network/server error leaves the result uncertain, the page retains the fields, disables further submission in that page session, and asks the guest to contact the host before resubmitting. A reload/new tab can still submit again. The script’s lock serializes writes; it does not prevent duplicate rows.

The browser validates names, attendance, bounds and lengths, and sends formula-like names as literal spreadsheet text. The supplied backend itself trusts incoming values; this client-side validation is not a server-side access or spam control. No private responses are exposed by the health endpoint. Do not expose the response Sheet or commit its exports.

## Updating the invitation

Edit `config.js` for the name/title, date, start times, venue, city, confirmed street address, optional verified Maps URL, and Apps Script URL. `endsAt` stays `null` until the end time is known. The current December date uses Pacific Standard Time (`-08:00`); update offsets if moving into daylight saving time.

Change wording in `index.html` and colors/spacing in `styles.css`. Keep the no-JavaScript event text in `index.html` consistent with configuration. Regenerate the fallback calendar after changing event details:

```sh
node tools/write-calendar.js
```

The browser generates its calendar from configuration. With no end time set, calendar apps may supply a default duration; that is not a confirmed event end. Directions currently open a venue search—confirm the street address and map pin before sharing.

## Preview and checks

Serve this folder over HTTP; opening the HTML as a `file://` URL will block JavaScript modules:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Open `http://localhost:8000`. Use Control-C to stop. The published site uses HTTPS.

Development tests require Node 20+, with no dependency installation:

```sh
node --test tests/*.test.js
```

See `TESTING.md` for the latest verification scope. `lib.js` contains the mapping to the supplied backend; `script.js` controls the form and confirmation.

## Deploying to GitHub Pages

Repository: `https://github.com/saumyag88/Shivani_Baby_Shower`.

Keep `index.html` at the repository root. In **Settings → Pages**, choose **Deploy from a branch → main → /(root)**. `.nojekyll` allows direct static hosting; no custom Actions workflow is needed. Push to `main` and wait for the Pages deployment to finish. The repository was made public with the host’s approval for free Pages hosting. All asset paths work under the repository subpath.

Before a commit, run the tests and `git diff --check`, review the diff, then commit and push. Keep guest data, spreadsheet exports and credentials out of Git. The public `/exec` endpoint URL is configuration, not a password; API keys, OAuth tokens and private spreadsheet IDs do not belong in frontend files.

## Troubleshooting

- **“Online RSVPs aren’t open yet”:** configure the full `/exec` URL and deploy the update.
- **Sign-in page instead of JSON:** check that the web app runs as you and allows **Anyone**, then test the `/exec` URL signed out. Workspace policies may restrict anonymous access.
- **Health check works but no response is saved:** run `setup()` from the Sheet-bound editor and verify its private `SPREADSHEET_ID` property. Check Apps Script’s **Executions** panel.
- **Unconfirmed RSVP:** inspect the Sheet before allowing a new submission. Do not blindly retry; the first request may already have written a row.
- **CORS/network error:** use the `/exec` URL, anonymous deployment, standard form encoding, and no custom request headers. Never use `no-cors` or a public proxy for guest details.
- **Headcount too high:** inspect repeated submissions and correct the affected rows. Summary totals all rows marked `yes`.
